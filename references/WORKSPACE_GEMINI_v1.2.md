# Antigravity 룩북프로젝트 워크스페이스 규칙 (`v1.2` 통합 작업트리 확정본)

이 파일은 `G:\내 드라이브\안티그레비티 룩북프로젝트`를 Antigravity 워크스페이스로 열었을 때 자동으로 적용되는 표준 작동 지침입니다. 기존 `JACC 단독` 작동 지침은 폐기하고, 실측 벤치마크로 검증된 **`v1.2` 멀티-엔진 작업트리 매커니즘**을 유일한 표준으로 적용합니다.

## 1. 언어 규칙
- 사용자가 어떤 언어로 질문하더라도 항상 **한국어**로 답변한다.
- 코드, 명령어, 파일 경로, 고유 기술 용어는 원문 그대로 두고 설명과 주석은 한국어로 작성한다.
- 아티팩트(계획서, 보고서 등)도 한국어로 작성한다.

## 2. 파일 저장 및 폴더 정리 규칙 (항상 적용)
- Antigravity에서 생성하거나 내려받는 **모든 결과물(프로젝트 결과물, 일반 채팅 결과물, 문서·계획서·이미지·코드·번역 시트·다운로드 파일 등 전부)**은 PC(C 드라이브, 바탕화면, 작업 폴더)가 아니라 이 구글 드라이브 폴더 **`G:\내 드라이브\Antigravity_산출물\`**에 저장한다.
- 모든 프로젝트·채팅 산출물 폴더 이름은 **`YYYY년 MM월 DD일 <상품명 또는 프로젝트/주제 대표명>`** 형식으로 시작한다.
  - 예: `2026년 11월 19일 롱코트`, `2026년 11월 19일 JACC 멀티엔진 업무배정 개발서`
- **상품·룩북 프로젝트**는 `_템플릿\YYYY년 MM월 DD일 (상품명)\` 기준의 표준 하위 폴더 구조를 따른다(`lookbook_postprocess.py --init-product`로 0토큰 생성):
  - `00_제미나이_첨부용_2장/` — Google Drive 최근 문서함 노출 및 1-Shot 고속 첨부용 참조 이미지 2장(`01_Image1_...`, `02_Image2_...`)
  - `01_상품속성_사이즈표/` — 상품속성표·사이즈표 원본 및 구글 스프레드시트로 자연스러운 한국어로 번역한 파일
  - `02_룩북이미지/` — 생성·검수·선별된 원본 룩북 이미지 및 `워터마크제거/` 클린본
  - `03_상세페이지_배너/` — 상세페이지 및 배너 이미지
  - `04_플랫폼별_룩북이미지/네이버_스마트스토어_1000x1000/` — 1000×1000 규격 룩북 이미지
  - `04_플랫폼별_룩북이미지/카카오스타일_1080x1296/` — 1080×1296 규격 룩북 이미지
  - `04_플랫폼별_룩북이미지/에이블리_900x1080/` — 900×1080 규격 룩북 이미지
- **일반 프로젝트 및 일반 채팅 결과물**도 동일하게 `YYYY년 MM월 DD일 <대표명>` 폴더에 저장하고, 작업 성격에 맞는 하위 폴더(`문서`, `소스`, `결과물` 등)로 정리한다.
- 새 폴더를 만들면 **`G:\내 드라이브\Antigravity_산출물\_INDEX.md`**에 한 줄 설명과 링크를 추가한다.
- 이미 있는 이름이면 덮어쓰지 않고 `(2)` 또는 `v02`를 붙인다.
- 바탕화면과 OneDrive에는 아무것도 만들지 않는다.
- 예외: 롤 파일(`G:\내 드라이브\League of Legends`) 등 별도 지정 위치가 있는 경우 해당 위치에 저장한다. 드라이브 밖에 저장해야 할 특별한 이유가 있으면 먼저 사용자에게 묻는다.

## 3. 파일 생성 후 링크 표시 및 파일 탐색기 자동 오픈 규칙 (항상 적용)
- 파일을 생성하면 응답에서 해당 파일 링크를 표시할 때, 마우스로 눌러 Windows 탐색기에서 파일이 들어 있는 폴더를 바로 열 수 있도록 **상위 폴더 경로(`file:///...`, 공백은 `%20` 인코딩)** 링크를 기본으로 함께 제공한다.
  - 예: `[파일명 (폴더 열기)](file:///G:/내%20드라이브/Antigravity_산출물/폴더명/)` · `[파일 보기](file:///G:/내%20드라이브/Antigravity_산출물/폴더명/파일명)`
- **파일 보여주기/열기 요청 시 파일 탐색기 즉시 실행 (사용자 지정 2026-11-20 영구 규칙)**:
  - 사용자가 특정 파일을 **보여달라**거나 **열어달라**고 요청할 때(또는 새 산출물 파일/폴더 생성을 완료했을 때), 해당 파일이 들어 있는 **상위 폴더 위치를 Windows 파일 탐색기로 바로 열어준다**.
  - 실행 명령: PowerShell `$shell = New-Object -ComObject Shell.Application; $shell.Explore("<파일이 있는 상위 폴더 경로>"); Start-Sleep -Seconds 2` (또는 `Invoke-Item -LiteralPath "<상위 폴더 경로>"`)를 실행해 Windows 탐색기 창이 실제로 화면에 열리게 한다.

## 6. `v1.2` 멀티-엔진 작업트리 및 이중 검증 표준 매커니즘 (항상 적용 · `JACC 단독` 폐기)
- **Tier 0 선제 차단 (0토큰)**: 파일 탐색·정돈·모델 로드·워터마크 제거·플랫폼 리사이즈·수치/해시/Verbatim 검증 등 결정적 작업은 LLM을 부르지 않고 로컬 스크립트(`G:\내 드라이브\Antigravity_산출물\JACC\task_tree_router.py`, `lookbook_postprocess.py`, `truth_verifier.py`, `MODEL\load_model.py`)로 0토큰 처리한다.
- **JACC의 역할 (`v1.2` 내부 서브모듈로만 작동)**:
  - `JACC`를 단독 워크플로우로 사용하지 않는다. 오직 **노드 간 전달 컨텍스트가 2,000토큰 이상일 때** 또는 **쿼터 스왑/세션 인수인계 시**에만 `G:\내 드라이브\Antigravity_산출물\JACC\jacc.py`(`ingest_transcript.py` 연동)를 호출해 원문 스팬(Verbatim 100%)을 압축한다(2,000토큰 미만은 즉시 스킵).
- **확정된 4대 업무 `v1.2` 작업트리**:
  1. **룩북 이미지 생성 (`v1.2` · 일반 Chrome `chrome-devtools` MCP 완전자동 표준)**:
     - **소규모 (1~2색상 · 총 6컷 이하)**: `swarm` 오버헤드 없이 **단일 턴에서 구조화 영문 프롬프트(`PRIORITY 1 직물 텍스처` + `MODEL/GARMENT 치수` + `prompt_patches.json` 필수 패치) 작성** → `00_제미나이_첨부용_2장` 스테이징 → 일반 Chrome(`127.0.0.1:9222`) Google Drive Picker **최근 문서함 직선택(`dblClick`)**으로 2장 고속 첨부(검색 0회) → 1컷 합격 시 같은 채팅에서 재첨부 없이(0초) 2~N컷 연속 생성 및 원본 자동 다운로드 → 합격 컷 AI 비전 검수 0토큰 스킵 → **`lookbook_postprocess.py` 0토큰 후처리**(OpenCV 별 워터마크 제거 + 3대 플랫폼 규격 변환).
     - **대규모 (3색상 이상 또는 총 7컷 이상)**: **`swarm` 병렬 팬아웃** 가동 (색상별 1컷 마스터 `Claude Opus 5.5 High` + 동일 색상 2~N컷 포즈 변주 `Gemini 4 Argon Medium` 독립 쿼터 풀 병렬) → 일반 Chrome 완전자동 생성 → `lookbook_postprocess.py` 0토큰 후처리.
     - **불합격 시에만 조건부 AI-to-AI 자가교정 루프 발동**: 7번 지침대로 즉시 새 채팅 + 강력 새로고침(`Ctrl+Shift+R` / `ignoreCache: true`) + 실패 원인을 `G:\내 드라이브\Antigravity_산출물\JACC\prompt_patches.json`에 영구 패치로 등록 후 재시도.
  2. **외부 다운로드 정돈**: `Tier 0` 100% 0토큰 우회 (모호한 파일명 예외 시에만 `Gemini 3.8 Flash low`).
  3. **스킬·도구 제작**: `Argon/Opus` 설계 → `Claude Sonnet 5.5` 구현(객관적 검증 툴 의무 내장) → `Tier 0` 자동 테스트 + `GPT-OSS 120B` 거짓말 감시자.
  4. **의류 홍보 SNS**: `Tier 0` 팩트 시트 추출 → `Neon` 브리프 → 플랫폼별 병렬 작성(`Sonnet`/`Hydrogen`/`3.8 Flash`) → 이중 검증 → 브라우저 배포.
- **이중 감시 게이트 의무화**: 모든 산출물은 **게이트 1 (`truth_verifier.py` 0토큰 객관적 검증)**과 **게이트 2 (이종 엔진 거짓말 감시자)**를 통과해야 하며, 실측 수치·exit code·파일 증거 없는 완료/정상 보고를 금지한다.

## 7. 룩북·행거샷 직물 텍스처 최우선 및 불합격 시 웹 Gemini 강력 리셋 규칙 (항상 적용)
- **직물 텍스처 1순위 필수 게이트**: 룩북 이미지 또는 행거샷 이미지를 생성할 때 가장 중요한 최우선 기준은 **옷의 직물 텍스처(원단 조직·질감·결)가 사실적으로 정확히 구현되는 것**이다. 직물 텍스처가 제대로 구현되지 않으면 다음 컷이나 후속 단계로 절대 진행하지 않는다.
- **불합격 시 즉시 새 채팅 + 강력 새로고침**: 룩북 이미지 생성 중 사용자가 **불합격 처리**하면, 기존 채팅창에서 누적 수정하지 않고 **그 즉시 Gemini 웹에서 새로운 채팅창(New Chat)을 연 뒤 반드시 강력 새로고침(`Ctrl+Shift+R` / `ignoreCache: true`)을 실행**하고 본래 작업을 이어나간다.

## 8. 룩북 생성 사전 선택 창 · 모델/의류 치수 텍스트 명시 · 2장 고정 첨부 규칙 (항상 적용)
1. **생성 전 선택 창(`ask_question`) 필수 질문**: 룩북 이미지 생성을 시작하기 전, 반드시 사용자에게 작은 선택 창(`ask_question` 도구)을 띄워 ① **사용할 모델의 성별 및 번호**(여성 모델 1~4번 / 남성메인모델)와 ② **생성할 룩북 이미지 컷 범위**(몇 번부터 몇 번까지 생성할지, 예: 1~3번 / 1~5번 / 단컷 등)를 먼저 확인받는다.
2. **채택 모델 신체 스펙 + 의류 세부 치수 텍스트 필수 기록**: 사용자가 모델 X번(예: 여성 모델 4번)을 채택하면, `G:\내 드라이브\Antigravity_산출물\MODEL\`에 등록된 해당 모델의 신체 스펙(`스펙.json`)과 착용시킬 옷의 세부 사이즈 치수를 반드시 프롬프트 텍스트에 직접 기록해 정확한 핏이 연출되게 한다.
3. **웹 Gemini 정확히 2장 첨부 + 나머지 전면 텍스트 작성**: 사용자가 모델 X번을 채택하면, Antigravity는 자동으로 Gemini 웹에 **① 모델 X번 사진(Image 1) + ② 이전 작업에서 생성된 행거샷 1장(Image 2), 총 2개의 이미지만 첨부**(`00_제미나이_첨부용_2장` 복사 후 Drive 최근 문서함 `dblClick` 고속 첨부 `43초` 컷, 상세 절차는 `G:\내 드라이브\안티그레비티 룩북프로젝트\이미지서칭시간단축지침.md` 및 `G:\내 드라이브\Antigravity_산출물\2026년 11월 19일 JACC 멀티엔진 업무배정 개발서\이미지서칭시간단축지침.md` 준수)하고, 그 외 모델 신체 치수·옷 세부 사이즈 치수 등 모든 조건은 텍스트 프롬프트로 작성한다.
